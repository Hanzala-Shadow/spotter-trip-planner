# Waypoint · Truck trip planner

React + Django assessment project. Enter a current location, pickup, dropoff and used cycle hours to get a road route, scheduled stops, directions and filled daily duty logs.

The implementation does not require an LLM, a database, a paid map key or a user account. The frontend and stateless Django API are configured for one Vercel project.

**Live app:** [https://spotter-trip-planner-indol.vercel.app/](https://spotter-trip-planner-indol.vercel.app/)

**Source:** [Hanzala-Shadow/spotter-trip-planner](https://github.com/Hanzala-Shadow/spotter-trip-planner) (private).

**Delivery status:** deployed on Vercel with the Django API and real routing verified. ## Run locally

Use Python 3.12 and Node.js 22 or newer. From the project root:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
npm ci
npm run build
python scripts/serve_preview.py
```

Open **http://127.0.0.1:8000**. This serves the actual production frontend and Django API together. On Windows activate with `.venv\Scripts\activate`.

For frontend hot reload, run these in two terminals:

```bash
.venv/bin/python backend/manage.py runserver 127.0.0.1:8000
npm run dev
```

Open http://127.0.0.1:5173; Vite proxies `/api` to Django. The preview server and `runserver` are local tools, not production servers.

## What it does

- Search and select US locations; preserve the required current → pickup → dropoff order.
- Plan against the 70-hour/8-day cycle, 11-hour driving limit, 14-hour window, 8-hour driving break, 10-hour daily rest and 34-hour restart.
- Schedule one hour each for pickup/dropoff and 30-minute fuel stops before exceeding 1,000 miles.
- Draw a connected four-status daily graph with 15-minute ticks, exact duty totals, mileage and remarks. Every sheet covers 24 hours in one home-terminal time base.
- Show route geometry, stops, delivery completion time, multi-day itinerary and directions.
- Print every daily sheet, even when another tab or day is selected.
- Show failed searches/routes clearly, flag changed inputs and require regeneration before printing updated logs.

Three sample presets cover a short trip, a longer trip needing fuel/rest, and a nearly exhausted cycle.

## Scope and assumptions

This is a **planning worksheet**, not a certified ELD or a truck-specific navigation service. OSRM's driving profile uses public road data; bridge clearance, truck restrictions, live traffic, legal parking and fuel availability are not verified. Stop coordinates lie along the planned route. Nearby city/state labels are approximate and optional.

A driver starts fully rested with a full tank. Current cycle used means prior on-duty work, not today's driving hours. Because prior daily totals are absent, rolling cycle recapture cannot be reconstructed; the planner conservatively uses a 34-hour restart. Full 10-hour rests are used rather than split-sleeper optimization. Driver identity and signature are never invented.

All logs use the **selected fixed terminal UTC offset**. Select the correct offset for the trip; automatic daylight-saving transitions are outside this assessment. Before departure and after completion on the boundary dates are explicitly marked as assumed off duty.

Public Photon, OSRM and OpenStreetMap services have no availability guarantee. Requests are bounded and cached; there is no location search on every keystroke or offline tile download. Switch provider URLs before sustained production traffic. User-entered locations are sent to the map services; the app has no trip database.
